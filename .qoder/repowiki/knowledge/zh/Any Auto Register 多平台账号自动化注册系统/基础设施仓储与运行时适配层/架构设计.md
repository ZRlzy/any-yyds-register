本模块是 `infrastructure` 层，面向 `domain` 领域模型提供 SQLModel/SQLAlchemy 持久化与外部系统调用适配，按职责拆分为若干仓库类：
- 数据仓储：`AccountsRepository`（账号 CRUD、导入导出、统计）、`ProxiesRepository`（代理池）、`TaskLogsRepository`（任务日志分页查询）、`TasksReadRepository`（从 application.tasks 读取任务状态并映射为领域对象）。
- Provider 元数据与配置：`ProviderDefinitionsRepository` 维护内置 mailbox/captcha/sms/proxy 定义种子数据并通过 `ensure_seeded` 同步到 `ProviderDefinitionModel`；`ProviderSettingsRepository` 管理用户配置项，依赖 definitions 解析字段默认值与认证模式；`ConfigRepository` 基于白名单过滤 `config_store` 中的键。
- 平台能力覆盖：`PlatformCapabilitiesRepository` 通过 `PlatformCapabilityOverrideModel` 覆盖各平台的 executor/oauth 能力。
- 运行时代码：`PlatformRuntime` 通过 `core.registry.get` 动态加载平台实例并执行 action，将返回的 token/overview 经 `patch_account_graph` 写回账户图；`SystemRuntime` 调用 `services.solver_manager` 重启本地验证码求解器；`HealthRuntime` 组合数据库连通性、平台注册表与 solver 状态输出健康探针。
依赖方向单向向下：本模块依赖 `core.db`、`core.account_graph`、`core.registry`、`domain.*` 与 `services.*`，不反向被 domain 或 core 引用，所有 SQL 操作统一通过 `Session(engine)` 上下文管理事务。
